# CONTEXT — Glosario del dominio

> **Opcional:** se crea desde 3 términos propios del dominio.
>
> Vocabulario compartido del proyecto: lo que cada término significa acá, para
> que la conversación, la documentación y el código usen las mismas palabras.
>
> **No** es especificación técnica (eso es `ARCHITECTURE.md`) ni esquema de
> datos (`DATA_MODEL.md`). Solo lenguaje.
>
> Se actualiza mientras se trabaja, no al final. Ver la skill
> `domain-modeling`.

## Cómo se usa

- Una entrada por término, en orden alfabético.
- Cada entrada dice qué **es**, qué **no** es (si hay confusión frecuente), y
  cómo se llama en el código (identificadores en inglés, `CORE.md § 2`).
- Si un término se descartó a favor de otro, dejarlo anotado como alias
  obsoleto en vez de borrarlo — así nadie lo reintroduce.

---

## Términos

### `NombreDelTérmino`

**Es:** _definición en una o dos frases._

**No es:** _el término con el que se suele confundir, y por qué son
distintos._ (Omitir si no aplica.)

**En el código:** `identifierName` / `TableName` / `/api/v1/resource`
